Outros estados

A mesma tela degrada com honestidade:

  • Sem chave / chave inválida (404 → null): o painel some, fica o formulário + aviso "Informe uma chave válida do tier profundo".
  • Cota esgotada (restante 0): anel cheio, número em tom de alerta (--exec-baixa), texto "Limite atingido — reinicia às 18:00".
  • Erro de rede: mensagem no tom do .erro, sem inventar número.
Segurança por construção. A consulta a /v1/quota roda numa Server Action: a chave fica server-side e jamais entra no bundle do cliente. O front só recebe os números agregados de consumo.

Spec de handoff

P1

Painel de cota — /desenvolvedores/cota

Objetivo
Mostrar consumo da chave (usado / limite / reinício) para quem está no tier profundo.
Dados
GET /v1/quota via nova consultarQuota(chave) em lib/api.ts (header Authorization, no-store, 404→null). Tipo novo RespostaQuota em lib/types.ts.
Componentes do DS
Novo: <BarraQuota> (SVG, padrão do Donut.tsx) + .cota-painel / .cota-form. Reusa tokens --exec-* para os limiares.
Estados
Com chave (mostrado) · sem chave / inválida (404→null: só o form + aviso) · cota esgotada (anel cheio, tom --exec-baixa) · erro de rede (tom .erro, sem número inventado).
Invariantes & gate
Form POST/Server Action: a chave vive server-side, nunca no bundle. requer chave — sem chave, esta é uma das poucas telas que não tem "estado pleno" demonstrável.
Prioridade
P1 — depende de chave.
